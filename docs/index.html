What it does

You hand it evidence JSON — ERC-8004 identity signals, Needle Drop verified history, First Spin published verdicts — and it returns a verdict: a score (0–1) with a published band and a full evidence trace, or a refusal when the evidence isn't there.

  • Admission: only verified evidence counts. claimed/pending/refuted count zero. Any disputed item refuses the whole run.
  • Sybil damping: issuer caps, identity clustering, self-assertion discount — applied openly, all damped items stay visible.
  • Determinism: no clock, no randomness, no network. Same input → byte-identical output, bound by input_sha256.
  • Provenance: scored verdicts are unanchored unless your input pins evidence with an anchor_ref.

Quickstart

git clone https://github.com/CumulativeWebInc/cwi-verdict-cli.git
cd cwi-verdict-cli
python3 -m verdict_cli example > evidence.json

# run-001/report.json  (canonical engine output)

Honesty

  • This tool scores evidence; it does not create trust. Garbage evidence in, garbage score out.
  • insufficient-data is the correct answer for new subjects — not a failure.
  • No "scored" demo exists on purpose. A scored example would need fabricated evidence.
  • No telemetry, no network, no accounts. Your evidence never leaves your machine.
